# wsFlow 프로토타입 사용 범위

2026-11-02 기준. wsFlow 0.1.0의 브라우저 GUI와 두 업무 모듈을 대상으로 한다. 현재 구현을 소스 ZIP으로 배포할 때의 안내이며, 안정판 수용이나 모든 PC에서의 무오류 보장을 뜻하지 않는다. 현재 수정 소스의 전체 CI 수용은 남아 있다.

## 바로 시작할 기능

| 업무 모듈 | 사용자 기능 | 프로토타입 사용 조건 |
|---|---|---|
| 워크스페이스 운영 | ROOT·기존 프로젝트 폴더 등록, 별칭·태그, 목록·대시보드, 빈 프로젝트 폴더 생성 | 본인 PC의 접근 가능한 폴더. 등록 해제는 실제 프로젝트 폴더 삭제가 아니다 |
| 워크스페이스 운영 | Git 상태·변경 파일·이력·커밋 내용·remote 조회 | Git 설치, 기존 Git 저장소. 원격 갱신 전 ↑/↓ 표시는 마지막 fetch 기준 |
| 워크스페이스 운영 | 규칙·스킬 출처 조사, 파일 내용/해시 대조, 개발 환경 준비 미리보기 | 파일 연결·사본 상태 확인 기능. AI가 그 내용을 실제 읽었다는 보장은 아니다 |
| 업무·일정 통합 | 로컬 캘린더의 월/주/날짜 상세, 프로젝트 필터, 기존 일지 업무·메모 조회 | 기존 일지는 조회하며 로컬 일정·독립 메모와 함께 표시 |
| 업무·일정 통합 | 로컬 일정·독립 메모 작성/수정/삭제, 초안·충돌 확인 | Google 저장 대상을 선택하지 않는 로컬 사용. 변경 내용을 확인하고 저장 |

위 기능은 계정 없이 로컬 중심으로 먼저 시험할 수 있는 권장 범위다. 프로젝트 폴더 생성과 로컬 일정·메모 저장은 실제 파일/DB를 변경한다.

## 설정·미리보기 후 사용할 기능

| 기능 | 가능한 일 | 조건·한계 |
|---|---|---|
| 템플릿·선택 스킬 관리 사본 | ROOT/프로젝트 준비, 선택 패키지 배포, 변경 대조·갱신, 소유한 사본 선택 해제 | 관리 사본 방식을 명시 선택하고 diff 확인. 직접 수정한 사본은 충돌 처리. 일반 임의 폴더 전체 버전관리·자동 병합 기능은 아니다 |
| 일반 파일 배포 | 원본 파일/폴더를 선택 프로젝트들에 복사, 신규/변경/동일 미리보기 | 기존 정책은 **덮어쓰기·자동 백업 없음**. 미리보기 후 필요한 원본 보관을 사용자가 준비. 관리 영역 보호를 우회할 수 없음 |
| Git 작업 | 선택 staging·commit, remote 설정, fetch, 고정 ff-only pull, 명시 push | 대상 저장소·remote·자격 확인. dirty/non-ff/충돌 때 pull 중단. 원격 push는 실제 외부 변경이며 사용자 확인 후 실행 |
| 프로젝트 Jira 메모 | `.workflow` 설정 작성/수정, 일지 메모 저장, 일일 수집·전체 업무 상태 | Jira 연결과 프로젝트 범위가 필요. 실제 계정 읽기 이력은 있으나 현재 소스의 모든 조직/프로젝트 조건을 재수용한 것은 아님 |
| Jira 조회 | 태스크·범위·날짜 기록 조회 | 계정 이메일/API token, 접근 권한·사이트·필드 매핑 필요. 복수 조직의 모든 스키마를 보장하지 않음 |
| Google 조회 | 계정 연결, 캘린더 선택·수집, 월/주 일정 표시 | 사용자의 Desktop OAuth client·동의 설정·조회 권한 필요. 실제 읽기 검증 이력과 현재 소스 전체 실사용 수용은 구분 |
| 세션 준비·관측 기록 | 시작 정보 복사, 사용자가 제출한 인식 근거 기록·오래됨 표시 | 새 Codex/Claude 세션은 사용자가 연다. 자동 실행·전역 스킬 배포·실제 AI 인식/준수 보장은 아님 |
| 모듈 구성 | 목록·설정·구성 미리보기, 신뢰 패키지 설치/비활성화/등록 해제·예약 후 재시작 | 현재 실행과 다음 실행 구분. 시험용 구성에서 먼저 확인. 무중단 교체·임의 DB 이관·장애 시 완전 복구는 미완료 |

스킬 정본은 선택한 ROOT/프로젝트의 지원 경로를 사용한다. 기존 사용자 전역 스킬 링크·공유 라이브러리·플러그인 전체를 자동 이관하거나 모두 관리하는 기능으로 해석하지 않는다.

## 아직 일반 사용자에게 권장하지 않는 범위

- Google 원격 일정 작성·양방향 수정·삭제와 충돌/불확실 전송 복구: 구현 및 합성 provider 시험은 있지만 전용 실제 계정의 전체 운영 수용이 남아 있다.
- Jira 코멘트/태스크 생성 등 원격 쓰기: 승인·재사용 차단·결과 미확인 처리 구현은 있지만 모든 실제 업무 효과의 수용은 남아 있다. 첫 배포의 기본 권장 사용은 조회·로컬 메모다. Jira Done 전이는 제공하지 않는다.
- 업무 데이터가 있는 모듈의 다른 구현 교체, 데이터 schema migration, 장애 중 교체/자동 되돌림: 일관 사본·복구 journal·기동 전 복구 및 연속성 작업이 남아 있다.
- ERP 실연동: `erp_demo`는 구조 확인용 읽기 전용 예제다.
- Codex/Claude의 자동 구동·스킬 실행/지침 준수 보장, 여러 사용자/PC의 공동 서버, 인터넷 공개 서비스: 현재 프로토타입의 제공 범위가 아니다.

## 소스 배포본 실행

현재 구조는 Python을 포함한 단독 EXE 설치 프로그램이 아니다. 쓰기 가능한 사용자 폴더에 풀고 Python·Git과 시간대 데이터를 준비한다. Python 3.14.3은 현재 시험 프로파일 중 하나다. Windows에서 `tzdata` 설치가 필요하며 개발 CI의 Node/Playwright는 앱 실행에는 필요 없다.

```powershell
python --version
git --version
python -m pip install tzdata==2025.3
python run.py
```

시간대 패키지는 배포본의 `requirements.txt` 또는 `ci/python-requirements.txt`에 고정한 버전을 우선한다. 표준 소스 배포본은 `run.cmd`를 사용할 수도 있다. 콘솔에 표시된 **토큰이 붙은 URL**로 브라우저를 연다. 기본 주소는 `127.0.0.1:8765`다.

초기 실행은 별도 프로토타입 등록 목록과 사용자 데이터 위치를 사용할 수 있다.

```powershell
$env:WSFLOW_DATA_DIR = 'D:\wsFlow-prototype-data'
python run.py --store 'D:\wsFlow-prototype-data\projects.json'
```

경로는 본인 PC에 맞게 정하고, 사용자 데이터 위치는 관리할 프로젝트/WF_HOME 밖에 둔다. 기본 등록 목록은 앱 폴더의 `projects.json`, 기본 사용자 데이터는 Windows `%APPDATA%/wsFlow`다. 실제 업무로 전환할 때 등록 목록과 사용자 데이터 위치를 함께 관리한다. Release 파일을 교체하는 것만으로 업무 DB migration·전체 복원을 수행하지 않는다.

첫 사용은 프로젝트 등록 → 상태/규칙 조회 → 로컬 캘린더·메모 → 미리보기 기반 템플릿/스킬 준비 순서를 권장한다. Jira/Google은 별도 시험 계정의 조회부터 확인한다.
