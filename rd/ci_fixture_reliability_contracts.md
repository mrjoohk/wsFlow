# P-027 — I4 시험 제어와 CI 증거 격리

F-065/F-074의 보강 계약(D-083/M-018). 이전 보고서·증거는 원문으로 보존한다. 제품 업무 코드와 실제 사용자 WF_HOME을 변경하지 않는다. 실제 Jira/Google 계정을 호출하지 않으며 원격 업무 쓰기 수는 0이다. CI는 기존에 승인된 source-only codex 브랜치와 GitHub Actions 범위다.

## 선택한 설계

I4 fixture는 이미 자신이 소유한 stdin/stdout을 갖는다. 이 채널에 ID가 있는 JSONL 요청·적용 확인을 추가하는 한 가지 최소 후보를 채택한다. 공유 파일 재시도·새 HTTP 관리 API를 추가할 필요가 없어 비교 구현은 생략한다. 제어·공급자 호출·통계 조회는 동일 lock에서 직렬화하며, 제어 확인 전에는 다음 UI 동작을 시작하지 않는다. 응답 ID 불일치/구문 오류/거절/시간 초과/자식 종료를 성공으로 처리하지 않는다. 오류가 난 채널은 재사용하지 않으며 종료에는 상한을 둔다. 명령을 자동 재실행해 시험 실패를 감추지 않는다. 기존 11개 I4 사례와 실제 앱/SQLite/합성 공급자 경계를 유지한다.

CI는 외부에서 상속한 출력 경로와 WF_HOME을 제거한다. 각 화면 실행은 별도 환경 사본을 받고, 변이 실행은 정상 unit/details/browser/graph 출력 경로를 상속하지 않는다. 혼합 Python/Node 변이에서 명세가 따로 지정한 경로는 각 변이 사본의 `{tmp}` 아래다. 원래 단계의 JSON이 다른 화면 출력으로 대체되지 않아야 한다.

화면 단계가 성공하면 전체 파일 목록과 SHA256을 기록하고 새 artifact 경로로 즉시 복사한다. 복사 중 원본/사본 변경과 이후 원본/사본/목록 변경은 FAIL이다. 마지막 수집은 보존한 화면 사본에 병합하지 않는다. 실패 단계의 raw 진단은 별도로 보존한다. 이는 OS 접근권한에 의한 불변성을 뜻하지 않으며 같은 사용자 악성 프로세스/전원 장애를 보장하지 않는다. 정상 자식 흐름 격리와 변경 탐지 계약이다. 과거 로그 재구성 경로는 이번 CI 수용에 사용하지 않는다.

## 검증·한계

F-065의 Windows 공유 파일 rename EPERM 메커니즘은 기존 탐침과 구분한다. 새 설계는 그 파일을 사용하지 않는다. 과거 최초 dialog timeout의 정확한 holder/원인은 단정하지 않는다. 실제 I4 반복/기존 UI 변이/두 Windows CI 프로파일에서 새 오류가 관측되는지 기록한다. 유한 반복 성공을 모든 부하에서 간헐 오류가 없다는 보장으로 확대하지 않는다.

F-074는 실제 mutation_runner 자식이 상속 경로로 쓰는 통제 입력으로 재현한다. 출력 변수 제거·단계 사본·복사 시점/후행 변경 탐지를 되돌리는 음성 대조를 추가한다. 정규 82개 화면 사례와 추가 5개 migration UI, 기존 242개 변이를 유지하며 신규 하네스 변이는 별도 집계한다. source fingerprint/commit/job/artifact SHA와 원 I7 17사례·화면/5 backend hash를 직접 대조한다. 실계정·실제 CLI 수용과 V2 미확보 표본은 이번 통과 범위 밖이다.
