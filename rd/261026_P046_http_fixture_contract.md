# P046 I7 인증 거부 HTTP 시험 계약

판단 근거: F199의 원 CI I7 실패와 P046 http_order_probe.json. 실제 루프백에서 헤더 뒤 본문을 서버 close 이후로 지연하면 원 요청은 동일 WinError10053 3/3, 본문 없는 명시 POST는 403 3/3이다. 원 CI의 패킷 순서를 직접 캡처한 것은 아니므로 호스트 보안 소프트웨어의 결함으로 추정하지 않는다.

토큰 거부는 본문 없이도 같은 실제 POST 경로를 통과하며 파일과 provider 호출을 바꾸지 않아야 한다. 헤더/본문의 별도 전송을 강제로 지연한 시험은 실서버의 close를 기다려 늦은 본문을 검출한다. 시험에서 사유를 명시한 assertion으로 실패시키므로 Windows의 구체적 오류번호에 의존하지 않는다. 원 전송의 실제 오류번호는 별도 진단의 원증거로 보존한다.

되돌림 음성은 (1) 구 `{}` 본문 전송 복원 (2) POST를 GET으로 바꾸는 method 누락 (3) 서버 token guard 제거다. 정상 baseline과 각 변이의 의도한 실패를 선정 CI에 넣는다. 인증/HTTP 제품 동작·시간제한·재시도 정책은 변경하지 않는다. 현재 source의 전체 회귀 및 두 Python CI·기존82화면/migration5/UID7·전체선정 변이·원 ZIP9·소비자를 다시 확인한다. 기존 원 실패/보고/사용자 파일·D092/D100 보류는 보존한다.
